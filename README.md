# mySportly

A native SwiftUI live TV app for iPhone and iPad, targeting iOS/iPadOS 27.0+ with Xcode 27.1. The first version focuses on organizing a large Xtream/M3U catalog, finding relevant live programs, and keeping personal choices under the user’s control.

## Open and run

Open `mySportly.xcodeproj`, choose the **mySportly** scheme, and select an iPhone or iPad running iOS 27 or later. Use the existing development team or your own signing team. The widget extension must use the same team and App Group.

The first launch offers **Connect a Source** and **Explore Sample Catalog**. Enter provider credentials in the app. Sample channels and schedules are explicitly labeled; their player opens Apple’s public HLS test stream. Add the launch argument `--demo` for an isolated, in-memory sample profile during UI testing.

## Implemented surfaces

- Native Live, Guide, Sports, Library, and Search tabs, adaptive iPad sidebar, soft scroll-edge headers, settings, forms, sheets, and AVKit controls. The dedicated Search screen uses an always-visible native search field in its navigation header, as do other searchable screens.
- Xtream Codes and M3U URL/file import, XMLTV guide, encrypted local catalog, secure source credentials, cancel/refresh/remove, guide mappings and time corrections. Native import steps show connection, channels, guide, and saving, with actual download sizes and progress bars when a total is known. Reopening uses the saved catalog; missing sources restore after that cache has loaded. Automatic Refresh defaults to a daily playlist and a guide-only update every six hours, with native frequency settings, per-device freshness, retry backoff, OS-scheduled background processing, and an overdue check on opening. Refresh never starts Jev.
- One Library holds saved channels, categories, channel groups, teams, leagues, and custom collections. Saving a league adds one item; its teams remain inside it. Saving or starring a team is a separate choice. Removing a star keeps the item saved. Existing sports saves and channel favorites are retained without a destructive migration.
- Settings → Where Data Comes From explains provider data, the bundled API-SPORTS reference, built-in recognition aids, personal choices, and Jev. Channel Details reports which mechanism chose its current category.
- iOS 27 App Schemas expose in-app search and opening saved Library items. App Shortcuts also play/save channels, open the guide, and refresh sources. System queries use a credential-free preferred-lineup snapshot; Spotlight indexes saved Library items only. Platform routing and actual voice activation are verified separately.
- Favorites, recent channels, custom groups, hide/rename/reorder/bulk editing, preferred variants, explicit variant separation, editable language/region preferences, and explained recommendations.
- Recently Watched supports a native trailing **Remove** swipe action for one history entry. The channel and favorites remain intact; the existing personal-data deletion ledger carries the history removal. Provider-labeled **No Event Streaming** slots stay in All Channels but are excluded from Home's automatic channel list and suggestions. Placeholder program titles do not become recommended programs or sports events, and shared-guide variants produce one Home recommendation.
- Local metadata rules recognize explicit country/language tags and category keywords in provider names/groups. Original channels and manual corrections are preserved. **My Lineup** is the default filter across Live, Guide, Sports, Search, and the player picker; **All Channels** and **Unclassified** remain available. Regions must match when selected. Known different languages are excluded; unknown languages can be included separately when the region matches. Country tags never establish audio language.
- Persistent shared-name groups with staged Jev category/subcategory decisions, dynamic paths, uncertainty review, manual corrections, and an entitlement-gated Apple PCC naming fallback. The old per-channel classifier is retired.
- Native Settings → AI contains personal category choices, region/language scope, Keychain connection, progress with Pause/Resume, and result review. Only the preferred audience is eligible for Jev, even while browsing All Channels. Unchanged decisions are reused after refresh and synced through private iCloud. Live uses one spinner in its soft navigation header while opening, syncing, refreshing, or organizing; loading and empty favorites stay out of the feed. Completed batches and the remaining queue survive interruptions. Apple's continued-processing Live Activity supports background work when the system grants it.
- Current/tonight/date guide, accessible list and iPad timeline, Sports events from EPG, teams/leagues, spoiler preferences, guide-description translation, and query interpretation against actual catalog candidates.
- Xtream imports its own EPG automatically when the optional XMLTV field is blank. Guide defaults to **Only Channels with Listings** for the selected time window; turn this off to review empty rows. **TV Guide Status** reports selected-lineup coverage, currently airing programs, missing IDs, unmatched IDs, and expired listings from the saved guide. Adding a custom URL replaces the source's guide; manual guide mapping remains available.
- Missing guide mappings are recovered locally from unique same-source/country channel names, quality variants, existing provider mappings, and exact local station call signs. Manual mappings (including an explicitly blank ID) win, valid provider IDs stay intact, and ambiguous/event/regional feeds are not guessed. Saved catalogs benefit without another download; future XMLTV imports also retain display-name aliases. Guide Mapping shows the match reason and supports **Use Automatic Mapping** or **Use Provider ID Only**.
- Catalog sorting, guide preparation, ranking, metadata suggestions, and variant detection run away from the main actor. Source/channel changes publish a consistent new snapshot; unrelated settings and group edits reuse it. Guide, channel management, group editing, Organizer, and the player channel picker render bounded batches with **Show More** controls. Full-catalog searching and selections remain available.
- Reopening shows the first screen from a small sealed launch snapshot: favorites, recent channels, the head of the lineup, and their next 24 hours of listings. The full catalog then decodes and prepares in the background, reusing saved metadata and guide-match stages when their input fingerprints match. Saved listings keep only now through +3 days. Debug builds print a `[Launch]` timeline measured from the kernel's process start, and `LaunchBudgetUITests` asserts the first screen within 1.5 s. Measurements are in `docs/product/evidence/instant-launch-2026-11/baseline.md`.
- Sports, Search, and Live recommendations share a local background index. Sports processes each shared guide once; its initial lists show 50 live/upcoming events, and Search shows 100 results. Typing, suggestions, and Return use local matching; **Ask Apple Intelligence** explicitly requests model interpretation.
- Native playback, compact player, previous channel, bounded reconnect, alternate variants, supplied audio/caption tracks, PiP/AirPlay, iPad multiview with connection accounting, supported Xtream catch-up, local reminders, and foreground HLS recording with local playback/storage management.
- The native player stays mounted during connection and reports actual first-frame readiness. Asset loading overlaps audio activation; available media can start before the initial buffering estimate finishes. Automatic buffering remains enabled, and brief stalls retain the current player item.
- SwiftData personal records and private CloudKit integration, optional local-only mode, App Intents/Shortcuts, and quick-access widgets.

Implementation is not the same as provider or hardware acceptance. Current evidence and limitations are tracked in [build progress](docs/product/build-progress.md) and the [V1 specification](docs/product/v1-spec.md).

## Integration setup

The app uses no mySportly account. CloudKit uses `iCloud.app.iska.mysportly`; the app and widget use `group.app.iska.mysportly`. Provision those identifiers for the selected Apple development team. Existing personal data stays local when cloud initialization fails. **Sync Personal Choices** takes effect after closing and reopening the app; previously synced cloud copies remain. Source secrets use Keychain, provider caches are encrypted and excluded from backup, and recordings remain local.

Apple Intelligence requires eligible hardware, an available model, and the person’s device settings. Ordinary channel browsing, manual organization, metadata suggestions, and keyword search work without it. Jev uses your personal TypeSafe key saved in each device’s Keychain. See the [group-decision integration](services/intelligence/README.md). No shared model key is embedded in the app. PCC stays disabled until Apple grants its entitlement and runtime availability is verified.

Native playback depends on the supplied codec/container. Recording supports unencrypted HLS with combined audio/video; encrypted media, byte ranges, separate audio renditions, and delta playlists are rejected explicitly. Recording requires an additional allowed provider connection and stops when the app leaves the foreground. Catch-up depends on provider support and the advertised retention window. Live scores and unattended DVR are outside this version’s agreed scope.

## Verification commands

```sh
swift test --scratch-path /private/tmp/mysportly-core-build --disable-sandbox
```

Run the app-state and UI tests from the Xcode scheme on a development-enabled physical device. This project is being verified on the user’s physical devices; do not download or boot simulators for this task. Device integration tests use a public HLS sample, temporary recordings, the private CloudKit container, and Apple Foundation Models where eligible. The opt-in two-device group sync test has also passed creation and deletion across the user's iPhone and iPad. An authorized real-provider import passed with 57,033 channels and 220,543 guide listings. A saved provider channel subsequently produced its first video frame in 3.98 seconds on iPhone and 2.26 seconds on iPad, tested sequentially within the provider's one-stream limit. These observations do not establish support for every feed/codec, long-session stability, all offline sync conflicts, AirPlay/PiP behavior, or representative model accuracy. See the evidence log for exact coverage.

The opt-in provider tests read a one-use `mySportly-provider-check.json` from the test host's temporary directory and delete that input afterward. Never put real credentials in source, launch arguments, or test fixtures. `ProviderDeviceTests` only checks importing; `ProviderImportUITests` uses the normal app and leaves the authorized source connected. Saved-source checks use a host-only `mySportly-provider-sync-check.json` marker and the connection already in Keychain. Run credential-bearing UI tests with a private result bundle, redact console output, and remove raw test artifacts after recording nonsecret results.

`CatalogQueryTests` includes a 57,033-channel/220,500-program synthetic workload, cancellation, source isolation, shared guides, manual mappings and time offsets. `ChannelDirectoryTests` checks ranking, variants, hidden channels/categories, and source removal. `NavigationResponsivenessTests` measures scheduling and main-actor responsiveness with the saved device catalog. `CatalogPerformanceUITests` covers navigation, Search, Sports, and first-frame rendering with Apple's sample stream. Saved-catalog navigation cases never refresh a provider. UI timings include XCTest interaction/snapshot overhead; compare the same configuration and catalog.

`ChannelMetadataTests` covers ambiguous tags, conservative language handling, shared country/language filtering, eligible sports feeds sharing a guide, manual overrides, and dated guide coverage. `MetadataCoverageTests` reads the saved physical-device catalog and reports numeric counts without credentials or provider requests. `LineupFilteringUITests` verifies native scope switching across Guide/Search and guide-status counts in an isolated sample profile.

`GuideMappingTests` covers source/country isolation, known language conflicts, quality and XMLTV aliases, local-affiliate ambiguity, timeshift/subchannel separation, manual blank overrides, cache compatibility, and inactive event slots. `MetadataCoverageTests` compares provider-only and recovered coverage on each saved device catalog. `HomeCleanupUITests` uses `--demo --demo-home-check` to verify single-item history removal in an isolated sample profile without playing a stream.

`SavedSourcePlaybackTests` requires an empty, one-use `mySportly-playback-check.enabled` file in the app's temporary directory. It consumes the marker, reads the existing Keychain connection, checks provider occupancy, and opens one saved US channel only when a slot is available. It reports numeric timings, stops playback afterward, and never exports credentials.

For device performance acceptance, build with `SWIFT_OPTIMIZATION_LEVEL=-O` while retaining the existing Debug signing/iCloud configuration. This avoids switching the user's development CloudKit environment just to get an optimized binary. No simulator is needed.

`LibraryRefreshIntentUITests/testSiriOpensTVGuide` is an opt-in physical-device voice acceptance check. Set `SPORTLY_TEST_SIRI=1` in the test runner environment after configuring Siri on that device. Typed App Intent route tests run independently; their success does not prove voice recognition. See [Library/refresh/Siri acceptance](docs/product/evidence/library-refresh-siri-2026-10-19/verification.md) for current passes and remaining device checks.
