# AI with OpenAI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace TypeSafe Jev and Apple Intelligence with the user's own OpenAI key and the Decisions API: background category sorting for channel groups, and a search fallback that runs only when local search finds nothing.

**Architecture:** A small `DecisionsClient` in `SportlyCore` builds and validates Decisions API requests and responses (`docs/product/openai-decisions-api.md`). `OpenAIGroupModel` implements the existing `GroupDecisionModel` protocol, so `GroupOrganizationPipeline` and its thresholds are unchanged. `SearchFallback` asks choice questions over known values (sport, league, team, time, language) and returns a structured interpretation that local search executes. The app stores the key in the Keychain, runs organization quietly in the background after the catalog is ready, and shows only key status in Settings.

**Spec:** `docs/superpowers/specs/2026-11-08-app-redesign-design.md`, sub-project 6, plus Error handling.

## Global Constraints

- Endpoint `POST https://api.openai.com/v1/decisions`, model `gpt-6-luna`, at most 400 questions per request, 2–255 choices per question.
- Key: Keychain only (`openai-api-key`, this device, not synced); never bundled, logged, synced or written to the catalog. Without a key everything works locally.
- Inputs: channel/group titles, provider folder labels, region/language labels, guide titles, the search text. Never credentials, stream URLs or viewing history. Group data goes in `input_json` parts so it is treated as data.
- Group categorization keeps the thresholds: auto-apply only at confidence ≥ 0.60 and selected probability ≥ 0.70; otherwise keep the local/provider category (needs review).
- Failures never show inline in Home or Search; Settings shows key status and the last problem. Retries happen on the next foreground or import.
- Removed: Jev client and key, Apple Foundation Models and PCC paths, Settings → AI screen, the organization Live Activity and its background-task plumbing.
- Not in this plan (recorded as follow-ups): duplicate-feed merging, AI game detection, display-name cleanup with the Responses API.

## Review Focus

1. **A refused question** in a batch: that group is marked for review; the rest of the batch applies. (Task 1)
2. **HTTP 401/403**: the key is reported invalid in Settings and background runs stop until the key changes. (Task 3)
3. **More than 400 groups pending**: requests are split at 400 questions. (Task 1)
4. **Search fallback is slow or fails**: local results (empty state) stay; nothing else appears. Timeout 4 s. (Task 4)
5. **Fallback picks a team the lineup doesn't carry**: the result is an empty search, not an error. (Task 4)
