# Home and New Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Live, Sports and Library tabs with an Apple TV–inspired Home inside a four-tab shell (Home · Guide · My Stuff · Search), rendered at launch from the saved snapshot.

**Architecture:** A pure `HomeContent.build` in `SportlyCore` turns games, follows, feed counts and favorite channels into the hero, Your teams, league rows and Your channels. The launch snapshot gains the sports data Home needs (games, teams, leagues, feed links, feed channels), so Home is complete on the first frame and refreshes when guide matching finishes. `HomeView` only lays that model out. The shell swaps tabs, moves Settings behind a profile button, and trims Settings.

**Tech Stack:** Swift 6, SwiftUI (iOS/iPadOS 27, Liquid Glass), Swift Testing for `SportlyCore`, XCTest UI tests.

**Spec:** `docs/superpowers/specs/2026-11-08-app-redesign-design.md`, sub-project 2 "New shell and Home" (plus its Error handling and Testing sections).

## Global Constraints

- Target iOS/iPadOS 27.0+, Xcode 27.1. File-system synchronized groups: new files under `mySportly/`, `CoreTests/` and `mySportlyUITests/` need no `project.pbxproj` edits.
- Core tests: `swift test --scratch-path /private/tmp/mysportly-core-build --disable-sandbox`
- App build: `xcodebuild build -project mySportly.xcodeproj -scheme mySportly -destination 'id=C68170D3-19CD-4A1B-B146-B6A8EB33AE3D' -derivedDataPath /private/tmp/mysportly-dd-sim`
- UI tests run on the iOS Simulator `iphone` (C68170D3-19CD-4A1B-B146-B6A8EB33AE3D), chosen by the user on 2026-11-08, with `-parallel-testing-enabled NO`. Launch-time assertions are not judged on the simulator.
- Tabs, exactly: **Home · Guide · My Stuff · Search**, `.tabViewStyle(.sidebarAdaptable)`.
- Settings contains exactly: Sources, Region and Language, Appearance. The existing AI entry stays until sub-project 6 replaces it with the OpenAI key.
- Home rendering makes no data request and no model call. Team and channel artwork loads through the existing caches (`SportsLogoCache`, `AsyncImage`).
- Empty rows are hidden. Copy stays minimal: no explanatory footers on Home.
- Every file holding channels is sealed with the existing catalog key (the launch snapshot already is).
- Interim follow model until sub-project 4: followed teams are `store.sportsLibrary` items with `kind == .team`; added leagues are those with `kind == .league`. Home reads them only through `HomeFollows`.
- Never put real credentials in tests, fixtures, or launch arguments.

## Review Focus

1. **Snapshot written by the previous build.** It has no `sports` key. It must still decode, with Home showing favorites and no games until matching finishes. (Task 2)
2. **Guide time passed without new data.** A game whose `guideEnd` (or start + 8 h) is behind the clock must leave Home on the next 30 s tick, and an upcoming game must become live. (Task 1)
3. **A followed team plays in an added league.** The game appears in Your teams and not again in that league's row. (Task 1)
4. **Channel hidden or source removed after the snapshot was written.** Hero, rows and feed counts never point at a channel that isn't in `channelIndex` or is hidden. (Tasks 2, 3)
5. **Nothing followed but favorites exist.** Home shows the single follow prompt plus Your channels, never an empty screen or a spinner. (Tasks 1, 5)

### Task 1: Home content model

**Files:**
- Create: `mySportly/Core/HomeContent.swift`
- Test: `CoreTests/HomeContentTests.swift`

**Interfaces:**
- Consumes: `SportsGame`, `SportsTeam`, `SportsLeague`, `SportsFeedLink`, `SportsLibraryItem.id`, `GuideProgram.isLive(at:)` (existing).
- Produces:
  - `public struct HomeFollows: Hashable, Sendable { public var teamIDs: Set<String>; public var leagueIDs: Set<String>; public var isEmpty: Bool }`. IDs are `SportsLibraryItem.id` values.
  - `public struct HomeSportsData: Codable, Sendable { public var games: [SportsGame]; public var teams: [String: SportsTeam]; public var leagues: [String: SportsLeague]; public var links: [String: [SportsFeedLink]] }` with `public init()` and `public func relevant(to follows: HomeFollows, at date: Date) -> HomeSportsData`. `relevant` keeps games that involve a followed team or an added league, with state live or start within 7 days, and only the teams, leagues and links those games reference.
  - `public enum HomeGameState: Hashable, Sendable { case live, upcoming }` and `extension SportsGame { public func homeState(at date: Date) -> HomeGameState? }`, which implements the state rule below. Task 2 reuses it.
  - `public struct HomeGame: Identifiable, Hashable, Sendable { public let game: SportsGame; public let state: HomeGameState; public let feedCount: Int }`, `id == game.id`
  - `public struct HomeChannel: Identifiable, Hashable, Sendable { public let channelID: String; public let program: GuideProgram? }`
  - `public enum HomeHero: Identifiable, Hashable, Sendable { case game(HomeGame); case channel(HomeChannel) }`
  - `public struct HomeLeagueRow: Identifiable, Hashable, Sendable { public let league: SportsLeague; public let games: [HomeGame] }`
  - `public struct HomeContent: Sendable { public var hero: [HomeHero]; public var teamGames: [HomeGame]; public var leagueRows: [HomeLeagueRow]; public var channels: [HomeChannel]; public var showsFollowPrompt: Bool }`
  - `public static func build(sports: HomeSportsData, follows: HomeFollows, feedCounts: [String: Int], favorites: [HomeChannel], at date: Date, calendar: Calendar = .current) -> HomeContent`

Rules for `build` (the tests pin each one):
- State: `.live` when `game.start <= date && game.canWatch(at: date)`. `.upcoming` when `game.start > date` and the status is `.scheduled` or `.live`. Otherwise the game is excluded. Games with `feedCounts[game.id] ?? 0 == 0` are excluded everywhere.
- `teamGames`: games where the home or away team's `libraryItem.id` is in `follows.teamIDs`, live within 7 days; live first (by start), then upcoming (by start).
- `leagueRows`: one row per added league that has games, ordered by league name. A game goes in a row when its league's `libraryItem.id` is in `follows.leagueIDs`, it is not in `teamGames`, and it is live or starts within 24 h. Within a row: live first, then by `feedCount` descending, then by start.
- `hero`, up to 3 distinct items, in priority order:
  1. Followed-team live games.
  2. Followed-team upcoming games starting on the same calendar day as `date`.
  3. Added-league games, live first, then upcoming within 24 h, each by `feedCount` descending, then by start.
  4. Favorites whose `program?.isLive(at: date) == true`.
- `channels`: `favorites` in the given order.
- `showsFollowPrompt == follows.isEmpty`.

- [ ] **Step 1: Write the failing tests** in `HomeContentTests`. Use fixed `now = Date(timeIntervalSince1970: 1_800_000_000)`, `calendar` in UTC, and a fixture with leagues NBA and NFL, teams Knicks, Celtics, Lakers (NBA), Cowboys (NFL).
  - `heroPrefersFollowedLiveThenTodayThenLeagueThenChannel`: Knicks live, Knicks tonight, a live NBA game Lakers–Celtics with `feedCount` 5, a favorite with a live program. With 4 candidates, `hero` is exactly the first three, in that order.
  - `followedTeamGameIsNotRepeatedInLeagueRow`: follow Knicks and NBA. `leagueRows.first?.games` has no Knicks game.
  - `gamesWithoutFeedsAreHidden`: `feedCounts` empty, so `teamGames`, `leagueRows` and `hero` are all empty.
  - `stateFollowsTheClock`: the same game is `.upcoming` at `start - 60`, `.live` at `start + 60`, and absent at `guideEnd + 60`.
  - `leagueRowWindowIs24Hours`: a game at `now + 25 h` is not in the league row, but is in `teamGames` when its team is followed.
  - `nothingFollowedShowsPromptAndChannels`: empty follows plus one favorite gives `showsFollowPrompt == true` and `channels.count == 1`.
  - `relevantKeepsOnlyFollowedGamesAndTheirReferences`: `relevant(to:)` drops an NFL game when only NBA is added, and drops the Cowboys team and that game's links.

- Test: `CoreTests/TeamColorTests.swift`

**Interfaces:**
- Produces:
  - `public struct RGB: Codable, Hashable, Sendable { public var red, green, blue: Double }`, values 0…1.
  - `public enum TeamColor { public static func dominant(rgba: [UInt8], width: Int, height: Int) -> RGB? }`
  - `SportsLogoCache.color(url: URL) async -> RGB?`. It renders the cached logo at 32×32 into an RGBA buffer, calls `dominant`, and memoizes per URL.

`dominant` rule: skip pixels with alpha < 128, or HSB saturation < 0.2, or brightness < 0.12 or > 0.95. Bucket the rest into 12 hue bins weighted by saturation, and return the mean color of the heaviest bin. Return `nil` when fewer than 2% of pixels qualify.
